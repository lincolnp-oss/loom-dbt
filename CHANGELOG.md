# Changelog

All notable changes to Loom are recorded here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and Loom follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Entries are written for practitioners deciding whether to upgrade: what changed for you, in the project's own vocabulary. (Development history in full - findings-register entries, decision records, pull requests - lives in the repository, not here.)

## Unreleased

## 0.1.0 (Alpha) - 2026-11-06

First public release. Loom is an authoring-time CLI for dbt: declare a project once in metadata, generate plain dbt from it, prove the built project still matches the declaration, and search the whole project - generated and hand-written models alike - as one inventory. Development before this release was pre-release and unversioned; the surface below is the surface that ships.

### Added

- The expression item (ADR 0037): a column item may carry `expression` - a non-empty verbatim SQL string under a required `alias` - instead of `source`, on staging `columns`, view `select_columns`, and gold/mart `aggregation.group_by` (rendered `expression AS alias` in the select list and as the expression in GROUP BY). The silver and obt `columns` name lists admit the same item beside plain column names and `{source, alias}` renames, as do dimension `attribute_columns` and fact `measure_columns` (ADR 0037 extension, 2026-11-05); scd2 `tracked_columns` and satellite `attribute_columns` stay name-only, and mapping items on satellite attributes - previously accepted and then misrendered - are now rejected at validation. Jinja delimiters and statement terminators are validation errors, identifiers are practitioner-asserted (the measures precedent), and the staging macro slot still combines only with `source`. `measures` is unchanged.
- The `filter` parameter (ADR 0038): staging, silver, dimension, fact, scd2_dimension and normalized_table accept an optional `filter` - a non-empty verbatim SQL predicate rendered into a WHERE over the model's input scan, never evaluated or identifier-checked by Loom (the expression item's posture; Jinja delimiters and statement terminators are validation errors). Silver applies it before dedup ranking, scd2_dimension on its snapshot's input select; with an incremental cursor the two compose as one WHERE, filter first. Instances without `filter` generate unchanged SQL. Joined and multi-input generators, per-input filters, HAVING and range joins remain post-Alpha bounds.

**Authoring and generation**

- A metadata model of named **pattern definitions** and **instance sets** (`metadata/patterns/`, `metadata/instances/`), plus descriptive **registrations** for hand-written models (`local/registrations/`) - one inventory for both.
- Authoring documents carry no `document_type` field: a document's kind is its directory (`metadata/patterns/`, `metadata/instances/`, `local/registrations/`), and each role validates its own required shape. The field was dropped before release because the paths already discriminate.
- Convert names two things it previously kept silent (owner rulings): a staging fit whose manifest materialization is not `view` carries a named materialization TODO on its draft record (the staging generator emits no materialization config), and a `convert --write` re-run now reports a **draft divergence** whenever an existing draft file differs from the draft the current assessment would write - the existing file is always kept; divergence is reported, never repaired.
- Documentation: the metadata reference now states staging's exactly-one-of sourcing rule as an obligation and documents `output_subpath`'s placeholder tokens ({name}, {generator}, {paradigm}, {owner}, {tags}); the `loom prove` account in the command reference states the strict form's accepted bound plainly - a model whose SQL wraps its projection in a CTE reports inconclusive and goes to the warehouse comparison.
- The generator parameter surface is consolidated (owner ruling, pre-release): link endpoints are one `endpoints` list of `{hub, key}` mappings; satellite and pit parents are one `parent` block (`{model, key}` for a hub parent, `{model, endpoints}` for a link parent) and a bridge's anchor is `parent: {model}`; every input-taking generator declares `input_models` (exactly one entry for the single-input generators; obt's `source_model` folds into it); hub provenance is the one `record_source` parameter, a string or a mapping keyed by input model; a reference table's satellite is the one-entry `satellites` list and its flattening shape is `variant` (was `mode`); a dimension's columns are `attribute_columns` (was `attributes`). Generated output is unchanged - equivalent metadata in the new forms generates byte-identical SQL.
- Pre-release cleanup: the guards that protected earlier pre-release forms are removed - retired command names now meet the ordinary unknown-command error instead of a rename pointer, the retired `local/registry/` directory is simply not scanned, and retired metadata fields (`kind`, `schema_version`, `test_opt_outs`, `unit_test_identity`, a `source` param) meet the ordinary unknown-parameter errors instead of retired-specific ones. Compatibility guards return after release, when there are real users and real renames to protect.
- `loom validate` and `loom generate`: generation renders everything before writing anything, refuses to overwrite a file that lacks the Loom provenance header (unless `--force`), supports `--select`, honours configured dbt output paths, and offers practitioner-controlled nested output layout (`output_subpath`).
- `loom generate --check` detects drift between metadata and the generated files on disk; `loom coverage` reconciles the inventory against the dbt manifest; `loom search` queries the inventory with the selector grammar (names, shape, owner, impact).
- One write convention across the CLI: the mutating commands (`generate`, `register`, `convert`, `snapshot-sources`) preview by default and write only with `--write` (or when `LOOM_WRITE` is set to a value other than `0`, `false` or `no`); every mutating run states its mode and the mode's source, previews end with the exact command to re-run with `--write` and carry would-write / would-change / unchanged counts, and `--format` and `--verbose` are accepted by every command. (`generate --dry-run` and the `--write-drafts` flag are retired in favour of the one convention.)
- Reports are human-readable text by default, with `--format json` as the stable machine-readable contract.
- Six agent skills ship with the package: `loom-core` (the shared rules every workload stands on), `loom-bootstrap`, `loom-adoption`, `loom-authoring`, `loom-ask` and `loom-maintenance` - task guidance for AI assistants working in a Loom project, carried inside the distribution at `src/loom/.agents/skills/` and mirrored at `skills/` in the repository. The two copies are kept byte-identical by a conformance test, which also checks the commands, flags and selector qualifiers the skills teach against the CLI itself.

- One selector grammar for search and selection: `loom search` accepts dbt-style selector arguments (bare names and `*` patterns, qualifiers such as `generator:`, `key:`, `column:`, `input:`, `is:`, `has:`, `doc:`, `kind:`, graph forms `+name` / `name+` / `@name` with depths and the `upstream:` / `downstream:` word forms), and the same `--select` / `--exclude` pair is available on every model-scoped command (`generate`, `convert`, `register`, `check`, `coverage`, `prove`, `search`, `validate`), each narrowing within its own pool. Set behaviour mirrors dbt: commas intersect within one selector, separate arguments union. **Changed behaviour:** `generate --select` previously read a comma-separated value as a union of names and `generator:` tokens; it now reads commas as intersection like everywhere else, so a spelling such as `--select generator:bronze,gamma` selects only the bronze model named `gamma` (repeat the flag to union). A search query carrying two or more shape qualifiers (`key:`, `column:`, `input:`, `generator:`, `paradigm:`) also returns close matches by shape overlap, labelled as banded; `--select` always stays strict. `loom validate --select` validates only the selected models' authoring documents, whole-document. dbt-style named selectors in `selectors.yml` are accepted as `selector:<name>`. The legacy search filter flags (`--text`, `--generator`, `--classification`, `--owner`, `--tag`, `--column`, `--key`, `--dependency`, `--paradigm`) are retired: selector arguments are the one search interface, and the retired spellings meet the ordinary unknown-option error.
- Search presentation: `loom search` with no query prints a project overview (counts by status, generator, owner and paradigm, documentation coverage, and suggested exception queries drawn from the project's actual state; the `has:` hygiene qualifiers count models, matching the overview's suggestions); a query prints a faceted table (counts over the returned set by status, kind, generator, owner, paradigm and provenance) with tier-2 objects (macros, sources, seeds, snapshots, tests, exposures) in grouped sections beneath the models - package groups presented exactly like project groups, capped past ten rows with their full count and a narrowing query - and a `kind:` qualifier promotes its kind to the primary table with kind-appropriate columns (every kind: provenance and package, plus the fact that kind is read by - macros: signature, arguments summary and used-by count, package-qualified so a project macro and a package macro sharing a name both appear; sources and seeds: downstream count; snapshots: the model snapshotted; tests: the model tested; exposures: upstream count). A query resolving to exactly one object prints its detail view, and a bare name borne by exactly one model prints that model's detail view with the other matches (its tests, above all) listed compactly beneath (for a model: keys, inputs, output columns with types and descriptions, graph counts with neighbours, test presence, file location; for a macro: signature, used-by, origin, and a slot-compatibility note derived from the signature - the signature read from the macro's own definition when the manifest declares no arguments - whether the macro can fill the staging column mapping slot, the one generator slot a macro can fill, which parameter the column fills by default, and how many `macro_args` a mapping must supply to reach the last argument without a default). `--fields` chooses the JSON record fields; `--count-only` and `--names-only` are the scripting forms. Search labels the manifest's age on its results and never refuses over staleness; the commands that guard on freshness refuse with the changed file named. On a terminal the output adapts to the terminal's width, reflowing tables without splitting tokens; piped and JSON output are unchanged.
- Shape similarity with explained overlap: every model reduces to a fingerprint (generator family, declared keys, declared inputs, output columns), and banded search ranks close matches by a weighted overlap against the described shape - keys 5, inputs 4, output columns 3, generator family 1, each scored as coverage, with a candidate sharing none of the described keys ranked below every candidate that shares the grain - each result carrying its score and a shares / differs account naming the actual elements. `loom search --similar-to <model>` runs the same comparison anchored on a named model's fingerprint instead of a described shape; the named model is excluded and shown as the reference header, and shape components that cannot be derived for it are named and excluded from scoring rather than scored as zero. Similarity output says "close matches" and "shares / differs"; it never asserts duplication.

**The generator set (18)**

- Report text follows one grammar across the report commands: verdict or yield first, counts before names, folded lists with `--verbose` to unfold, and a `Next:` line when an action exists; the JSON payload is unchanged.
- Staging over native dbt sources (or inline sources, completed by generating their declarations, with optional source freshness), with project-authored column macros.
- Data Vault: hubs (single- or multi-source, opt-in persistent retention and per-source provenance), links (n-ary, non-historised event links with payload), satellites (standard, non-historised, record-tracking, multi-active and effectivity variants), point-in-time tables, bridge tables, and reference constructs (reference hub / satellite / table).
- Kimball: facts (transaction, periodic-snapshot and accumulating-snapshot flavours), dimensions with surrogate keys, and SCD2 dimensions in Types 2, 3 and 6 over dbt snapshots.
- Medallion bronze / silver / gold, 3NF normalized tables and reporting views, one-big-table, and composed marts - paradigms mix freely in one project; nothing converts one paradigm into another.

**Generated tests, catalogue and contracts**

- Data tests derived from generator contracts (unique, not-null, relationships), default-on with no opt-out.
- dbt unit tests declared in instance metadata and generated.
- Generated model properties publish each model's description, columns and types to the dbt catalogue; practitioners may declare column documentation and types in metadata.
- Enforced dbt model contracts are available as an explicit per-model opt-in - never by default.
- Local source-structure inspection and schema baselines (opt-in, read-only) against DuckDB sources.

**Incremental loading**

- An opt-in `incremental` declaration per generator (link, bronze, normalized table, fact, dimension, silver, gold; hubs via their retention switch), with per-dialect strategy validation at generate time and documented recomputation semantics per family.

**Migration of existing projects**

- `loom register` drafts a registration for every model in a dbt manifest; `loom convert` drafts for the models unknown to Loom - a conversion draft where a model's output shape fits a generator, an authoring draft (declared facts copied, the transform left as one named authoring hole) for the rest - and `loom plan` phases the consumer work. The entries below record the adoption programme's final state: one unified draft class, a readiness account per draft, and registration as the gate on drafting.
- Drafts harvest what the project already declares, verbatim: descriptions, owners, column documentation and types, incremental configuration, and the source models' SQL comments as rationale.
- A staging conversion draft never invents a column mapping: an output the manifest's documented source columns cannot pair (beyond exact matches and one guarded rename inference) is drafted as an unresolved placeholder, `source: __TODO__`, with the unresolved outputs and candidate source columns named in the evidence and review todos; `loom validate` rejects the sentinel, so a placeholder cannot be promoted by accident. An output the model's own SQL names beyond the manifest's documented columns is accounted for the same way - drafted as a named placeholder, with the gap stated in the evidence - so a fit draft's readiness never certifies an incomplete column set in silence.
- Conversion fits no longer silently drop what a generator cannot express: a single-source model carrying a row filter (WHERE), a plain-SQL column expression, or a LIMIT is not drafted as a staging or bronze fit - the no-fit reason names the construct instead.
- Convert writes one unified draft class in `local/drafts/` (replacing the conversion-draft and scaffold sets in `local/migration-drafts/`): a draft record carrying the generator, its basis (`fit` or `authoring`), the evidence or no-fit account, and the declared interface copied verbatim - now attached to fit drafts too, not only to authoring drafts - plus a final-form instance document and, where the project has no pattern for the generator, a synthesised pattern under its final name (`<generator>_pattern`). Promotion is a file move plus registration cleanup: no rename step, no content edits at promotion time.
- Convert and check now verify macro references against the manifest (Tier 1): convert drafts a staging macro column only for a verified name-style call in the model's final projection; an unverifiable slot-shaped call drafts as the plain mapping and stands as an evidence hole naming the macro; other macro shapes are named in the no-fit reason. `loom check` fails on a generated instance whose macro reference is missing from the manifest or arity-mismatched.
- New command `loom prove`: the static equivalence stage (strict form). Over two practitioner-compiled manifests at fixed names (`local/equivalence/original.manifest.json`, `local/equivalence/candidate.manifest.json`, from `dbt compile` of the original and converted projects), it reports per model *proven* or *inconclusive* - never a static disproof. Proven requires all of: same adapter on both manifests; the model present in both; neither side stateful (snapshots and incremental models are never statically proven); compiled code with no unresolved Jinja and no run-varying values outside the declared differences; every original column counterparted, with candidate additions admitted only as `__`-prefixed declared differences (no declared mappings); and compiled SQL identical after a deliberately minimal normalisation (comments, whitespace, case outside literals and quoted identifiers, trailing semicolons, and the candidate's `__` select items removed). Absent manifests report the stage as not run (exit 0) and the warehouse proof proceeds as before; the JSON output is the proof record the playbook's recording step cites.
- `loom create-new data-test <model> --test <name> [--column <col>]`: prints a `generic_tests:` carriage declaration for a generated model or the dbt-YAML `models:` fragment for a hand-written one. The named column is verified against derivable/documented columns (refused when derivably absent, commented when unverifiable); tests whose arguments Loom cannot know carry the `__TODO__` kwargs sentinel the validator rejects; an opted-out model warns about the carriage conflict.
- Tests carriage, manifest side: convert fit drafts now copy the model's manifest generic tests into the draft's `generic_tests` (keyed on the attached model; dbt-injected kwargs dropped; a declared warn severity preserved; singular tests never copied). `loom check` warns when a carried declaration exactly duplicates a generator-emitted test, and when a declaration is not attested by the manifest's test nodes - the latter is an error under the new `loom check --strict`.
- Generic-test carriage: a new common parameter `generic_tests` on every generator declares practitioner generic (data) tests - `{test, column_name?, kwargs?, config?}`, kwargs/config verbatim - and `loom generate` merges them into the model's properties document alongside generator-emitted data tests. Loom never validates test names (dbt resolves them from installed packages). `skip_properties_document` + `generic_tests` on one model is now a validation error naming the conflict.
- The staging column `macro:` slot now accepts package macros (Tier 1): a dotted `package.name` reference alongside the bare project-macro name. `loom validate` warns "unverified package macro" for dotted references and never blocks (it has no manifest); bare names keep the verified project-macro rule. `loom generate` renders the invocation as declared. Verification against the manifest (existence and arity, defaults read from the macro signature) lands with the convert/check surfaces.
- Staging macro columns gain `macro_column_param` (Tier 2): an optional integer on a macro column pinning the 1-based argument position the source column fills, for macro signatures that are not column-first (e.g. `dbt.date_trunc(datepart, date)`); `macro_args` carries the remaining literal arguments in signature order, and existing `macro:` instances render byte-identically (an explicit position of 1 is the slot's own form). `loom validate` bounds the position by the declared call; convert drafts a Tier 2 column for a verified final-projection call whose source column sits in a later position - resolving it against the source's documented columns and naming the position and signature parameter in the evidence - while an embedded macro call (Tier 3) stays in the authoring class with the macro path named in the no-fit reason.
- New envelope key `skip_properties_document` (instance params or pattern defaults): `loom generate` emits no properties document for the model - and no merged `data_<model>.yml` where the generator emits data tests - naming each skip in its report; a leftover document from before the opt-out is reported (stale under `--check`), never deleted. `loom check` warns when an opted-out model has no practitioner description in the manifest. Convert drafts carrying declared tests or semantic models suggest the key in their promotion steps. This ends the delete-after-every-generate recipe for converted models that keep practitioner YAML.
- The semantic layer is visible in register/convert reporting: `seen_but_not_assessed` counts the manifest's semantic models, metrics and saved queries alongside node types; each model's downstream-consumer count is decomposed by kind (in the flag and as `consumers_by_kind`); and the metrics and saved queries reachable from a model via its semantic models are named in its record (`semantic_layer`) and in a new interface flag. Plan's manifest consumers already named them and now pin that in tests. Reporting only - the generation boundary is unchanged.
- `loom --help` now groups the commands by task family (author / adopt / verify / sources), and the migration playbook is renamed `docs/adoption-playbook.md` (cross-references updated); the retired "bundle" artefact vocabulary is gone from draft records and docs - a draft is a draft record, its instance, and its pattern.
- `loom scaffold` is now `loom create-new`: the kind argument is retained, and `create-new unit-test` now also serves hand-written (manifest-only) models, printing the dbt-YAML `unit_tests:` form - given inputs derived from the manifest's `depends_on`, rows keyed by documented columns, degrading to empty rows with a comment where documentation is absent. The `data-test` kind arrives with the tests-carriage work in this release - see the carriage entries in this section. The retired `scaffold` name errors with a pointer, like the other renames.
- Three commands are renamed (the retired names error with a pointer to the new name and are not aliases): `loom check-coverage` is now `loom coverage`, `loom capture-source-structure` is now `loom snapshot-sources`, and `loom compare-source-structure` is now `loom diff-sources`.
- Convert now reports readiness instead of yields, and registration gates drafting: the summary's three yields (`registered` / `scaffolded` / `conversion_drafted`) are replaced by the readiness distribution (`ready_to_promote` / `needs_authoring` / `not_draftable`), each model carrying a derived account - named holes, kinded authoring vs evidence, inexpressible constructs as blockers - in the draft record and the JSON, never in the instance, re-derived every run with transitions reported. By default convert drafts only models unknown to Loom: a registration withdraws a model from the drafting pool (deleting it returns the model), and the new `--include-registered` flag restores the previous reach.
- Safety rails: the assessment refuses a stale manifest, declares the manifest's compilation provenance (fit calibration assumes a parse-produced manifest), annotates build-produced results at the point of use, and flags what a conversion would not carry (contracts, grants, warehouse config, groups, materializations). Fit proposals are heuristic output-shape matches; the equivalence proof in the adoption playbook remains the gate for every swap.
- The CLI surface is three flat verbs; there is no `migration` command group and no aliases for retired names.

**Dialects**

- Every generator's SQL is parse-checked under eight dialect grammars (DuckDB, PostgreSQL, ClickHouse, Snowflake, BigQuery, Redshift, Databricks, Azure Synapse). DuckDB is the one executed and supported dialect (in CI); the other seven are parse-checked only - a syntax guarantee, not adapter compatibility. PostgreSQL, ClickHouse and Databricks carry historical development validation, recorded once in the architecture document's compatibility and evidence table; it is not a support tier.
- Declared `unit_tests` now cover the source-fed generators and satellite: a staging or bronze instance may declare unit tests whose `given` input names the model's own source table (generation renders it in dbt's `source('name', 'table')` form, and validation checks it against the declared source), and satellite instances accept declarations like the other Data Vault generators. Only `scd2_dimension` remains excluded, because dbt unit tests target models and its model under test is a snapshot.

### Fixed

- Convert's authoring drafts now account for every output of the original model's final projection: where expression items are pre-placed in a staging draft's `columns`, each remaining projected output is drafted as an unresolved placeholder (`source: __TODO__`) in projection order instead of being left out of the mapping, so the readiness account names each unmapped output as a hole and the draft cannot report ready to promote while any projected output is unmapped. Previously the pre-placed expression items alone read as a complete mapping: completing the draft's other holes certified it ready, and generation silently dropped the unmapped outputs. A projection the enumeration cannot fully name (a star mixed with explicit items, or an item that does not name its output plainly) is accounted by a caveat on the draft instead. Fit drafts are unchanged.
- The authoring record's hole note for a staging scaffold now names both forms a computation on one column takes - the expression item (`{expression, alias}`, the computation as plain SQL text) and the column's macro slot (`{source, alias, macro}`) - where it previously named the macro slot only and denied the SQL-text form the same draft pre-places.
- Duplicate generic tests at generation: a `generic_tests` declaration duplicating a generator-emitted test (same test, column and kwargs) is now emitted once instead of twice, where the duplicate pair failed `dbt parse` ("dbt found two data_tests with the name ..."). A `config` the declaration carries is merged onto the single emitted entry rather than dropped, and `loom check`'s duplicate-test warning now describes this behaviour. Convert's carriage, which copies a source model's tests onto fitted gold and mart measure aliases the renderer also emits tests for, produced the duplicate unaided.
- A hand-declared generic test whose `kwargs` carry dbt's reserved `model` argument (directly, or inside the `arguments:` wrapper) is now a validation error naming the reserved argument, instead of rendering verbatim into a `dbt parse` failure. `column_name` is not reserved and stays accepted.
- The gold and mart `aggregation` mapping is closed: keys other than `group_by` and `measures` are validation errors, where a nested `filter` previously passed validation and was silently ignored by the renderer. The same closure now covers measure items, `parent` blocks (satellite, pit and bridge), `joins` entries and view `select_columns` items, each rejecting unknown keys with the accepted keys listed.
- Search freshness now honours search's contract: `dbt_project.yml` edits after a parse no longer make `loom search` refuse - the project-file freshness check moved from the manifest read (where it sat below every caller's tolerance switch) into the guarded freshness walk, so guarded commands (check, coverage, register, convert) keep refusing with the file named alongside every other stale file, while search answers and labels the manifest's age in its results output as well as its overview. (`loom plan` and scoped `validate`, which never ran the guarded walk, now tolerate a project-file edit as they already tolerated model edits.)
- `loom prove` honesty on partially documented projects: a candidate column with no counterpart among the original's documented columns is now described in those terms (the original's documentation may be incomplete) instead of as a candidate addition, and the report gains a documentation-coverage note (text and JSON: `documentation_partial`) naming compared models whose original documentation is partial. Verdicts are unchanged - inconclusive stays inconclusive.
- `loom prove`'s closing guidance points to the warehouse comparison at adoption playbook Step 6, not Step 3.
- `source_ref` and `inline_source` now genuinely require `name` and `table`: an instance missing either key fails `loom validate` naming the missing key, instead of validating clean and generating `source('name', 'unknown')` to fail at dbt compile. The staging renderer no longer substitutes an 'unknown' placeholder - an unvalidated path fails in code rather than in generated SQL. (`schema` keeps its real default and stays optional.)
- Scoped `loom validate` evaluates its selector over the inventory's model records only, as designed: a tier-2 object whose identity is its bare name (a source) named in `--select` now errors as an unmatched model selection instead of being reported as a selected model with no authoring documents. The closing line of a validate run, scoped and unscoped alike, names what was validated - the entries and the authoring documents carrying them - instead of counting "inventory entries".
- Search presentation, closing the implementation audit's polish list: a `kind:`-promoted table folds past ten rows under the same capping rule as the grouped tier-2 sections (the first ten rows, the folded count and a narrowing query) instead of printing in full; text `--count-only` under shape banding distinguishes the full and close counts with the headline's labels; the no-query overview shows the total object count ahead of its per-category census and pluralises its suggested queries correctly at a count of one ("1 orphaned model"); a zero-result diagnosis lists the facet values that exist for the `doc:`, `has:` and `path:` qualifiers, as it already did for the other qualifiers; and bare-term ranking orders a model-description match before a column-description match, as designed. Shell completion's deferral past the Alpha is recorded in the command reference.
- `loom generate`, `loom coverage` and `loom check` name the shadowed state instead of prescribing a remedy that cannot succeed: when a generated model and a hand-written model share a name - the generate-before-remove window of a conversion swap - the three commands report the shadowed pair, the state and the way out, where coverage and check previously sent the practitioner to a `dbt parse` that the duplicate name makes impossible.
- Search's terminal-width bounds are measured in display columns rather than bytes: the width adaptation counts each character's terminal width (the truncation marker is one column and three bytes), via the `wcwidth` package, now a declared runtime dependency.
- Gold's authorable `joins` entries now render LEFT JOIN, matching obt and view: a multi-input gold model keeps driving-input rows whose join keys are unmatched in a joined input, aggregating them with nulls, where the plain (inner) join it rendered before dropped those rows from the aggregate entirely. The join type stays fixed - no parameter chooses it.
- Documentation: two signposts for frictions a cold reader meets. The metadata reference and loom-authoring now state the consequence of gold's fixed LEFT JOINs for generated tests: a measure over a joined input is NULL on unmatched rows (a count of a joined column is 0), the `not_null` test gold emits on every measure alias fails for such a model at build time rather than the row being lost, and declaring the test on the instance through `generic_tests` with a config is the remedy, since a hand edit to the generated tests document does not survive regeneration. The adoption playbook and loom-adoption now state that the `schema` of an `inline_source` binding for a seed is the warehouse schema the seed materialises into under the project's dbt profile (the target schema, adjusted by any `+schema` configured for the seed), not the name of the seeds directory, and that the manifest records each seed's resolved schema.

- Em-dashes (U+2014) removed from every Loom-authored string, comment and document in the shipped tree: they render incorrectly in some practitioner-facing artefacts, so report text, help text, draft notes and the documentation now use plain hyphens. Practitioner-authored content is untouched, as always: Loom carries declared text byte-for-byte, dashes included.
- YAML merge keys (`<<: *template`) in practitioner dbt YAML and Loom metadata now load with standard YAML semantics - merged values take effect, explicit keys override merged ones. Previously `loom validate` rejected any file using the idiom with a constructor error for the merge tag: the duplicate-key YAML loader had dropped PyYAML's merge-expansion step. Duplicate explicit keys are still rejected, including inside a mapping that also merges.
- Staging macro columns now generate a plain Jinja expression call (`{{ macro(...) }}`), which dbt compiles. The earlier rendering used the `{% call %}` block form, which dbt rejects for ordinary macros, so a generated staging model carrying a `macro:` column could not build at all; the declaration, the argument assembly and `macro_column_param` are unchanged - only the emitted invocation form changed. A runtime test now builds macro-carrying staging models under dbt.
- `loom convert` no longer doubles a generator's layer directory into a drafted `output_subpath`. A staging model living in the conventional `models/staging/` directory previously drafted `output_subpath: staging`, so a draft promoted as written generated to `models/_generated/staging/staging/<model>.sql`; the draft now recognises the leading segment as the generator's own (generation adds it) and proposes no subpath, with the review note naming the flat generated path. Nesting below the layer segment is still carried over (`models/staging/ecom/` drafts `ecom`), and a layer-named segment that does not lead the path is untouched.
- A pre-release quality pass (a clean-frame assessment of the certified tree, followed by a full fix pass) corrected the shipped text layer: both example projects' tutorials named a retired command (`loom check-coverage`) among other instruction errors, one tutorial recipe omitted the `--write` its own flow required, and the README's adoption summary inverted the playbook's convert-first order. The examples' command lines and flags are now guarded by a conformance test against the CLI itself.
- The same pass corrected behaviour the entries above now describe in its corrected form: search hygiene counts spanning every record kind, same-named macros collapsing to one record across packages, fabricated empty signatures for undocumented macros, a search freshness refusal its contract forbids, fit drafts omitting undocumented output columns, the unit-test scaffold duplicating a given-row column fed both plainly and through a macro, and generated files ending without a trailing newline (every renderer now appends exactly one).

### Changed

- Every generator-managed bookkeeping column now carries the `__` system prefix, so a generated model's own columns are distinguishable from declared interface at a glance: the provenance column is `__record_source` (the `record_source` / `record_sources` parameters that declare its value keep their names), satellite hash diffs are `__hash_diff`, SCD2 views and satellite effectivity windows expose `__valid_from` / `__valid_to` / `__is_deleted`, point-in-time tables carry `__snapshot_date` and one `__<satellite>_ldts` load-timestamp column per satellite, and an equal-weighted bridge's factor is `__weighting_factor`. Declared columns - business keys, hash keys, tracked and attribute columns - are unchanged. `loom validate` now reports a declared column that collides with a generated system column as one named error; rename the declared column, as system columns are fixed and are never renamed per project.
- Generated output carries no tool branding anywhere it lands in your project: the load-timestamp column is named `__loaded_at` on every generator that emits one (development builds called it `loom_loaded_at`); the internal aliases and guard CTEs inside generated SQL use the same `__` system namespace (`__rn`, `__window`, `__link_guard` and friends) instead of `loom_`-prefixed names; generated staging models and generated test files live under a single `models/_generated/` directory (`_generated/staging/` and `_generated/tests/`), and the shared source-declaration file inside the staging directory is named `sources.yml`. Meanings and behaviour are unchanged throughout - the column still records first-insert time on persistent hubs and satellites, rebuild time on table-materialised models, the dedup ordering inherited by silver models, and part of the aggregate grain on gold and mart outputs - only the names your project inherits are now project-appropriate throughout.
- Load timestamps (`__loaded_at`) are naive local timestamps on every dialect, DuckDB included.
- Hand-written and generated models are equal citizens of the inventory: registration is a permanent, legitimate end state, not a step on the way to conversion.
- Metadata documents carry no format version: pattern definitions, instance sets, registrations, assessment drafts and source-structure baselines no longer state a `format_version`, and Loom does not read one. Practitioners pin the Loom release they use; if a future release changes the metadata format incompatibly, the change will be called out here with an explicit migration path.
